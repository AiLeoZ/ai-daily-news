# AI 每日资讯 · 内容生成规范（模型无关）

> 本文件是「AI 新闻」与「GitHub 趋势」两块内容的**唯一生成标准**。
> 自动化流水线在执行「生成 AI 新闻」与「生成 GitHub 趋势」两步时，**必须先读取本文件并严格照做**，
> 以确保无论底层使用哪种大模型（如 Hy3 / DeepSeek 等），产出的结构、条数、文风都保持一致、稳定可复现。
>
> 原则：把"靠模型发挥"的部分全部变成"确定的规则 + 范例"，模型只负责按规则把真实信息填进来。

---

## 0. 通用规则（两块都适用）

- **语言**：简体中文。
- **数据真实性**：所有数字、项目名、日期、人物 / 公司名必须来自 `data/collected/` 的真实抓取或联网搜索结果，**禁止编造**。来源不足时宁可少列几条或标「暂无描述」，不可虚构。
- **时间窗口**：近 7 天（含当天，时区 Asia/Shanghai）。
- **时间顺序**：所有条目**严格时间倒序**（越近越靠前）。
- **发布前必须执行文末「自检清单」**，全部通过后才调用 `filter.py`。

## 1. AI 新闻

### 1.1 选材与条数

- **条数固定为 10 条**。若近 7 天真实重要动态确实不足 10 条，可取 8–10 条，但**不得为凑数编造**低质内容。
- 来源：结合 `data/collected/rss_$DATE.json` 候选 + 联网搜索（参考 `sources/keywords.yaml` 分组）。
- 分类规则（确定性，不靠主观判断）：
  - **今日要闻**：发生日期 == 当天（即标题日期与 `$DATE` 相同）。**最多 4 条、至少 1 条**。
  - **近期其他要闻**：发生日期 < 当天，按时间倒序排列其余条目，承接今日要闻序号连续编号。

### 1.2 Markdown 结构（严格照此）

```
## 🔝 今日要闻

### 1. 标题（当天日期，形如 2026-08-03）

事件说明段落（1–3 段，交代发生了什么、关键数字、为什么重要）。

- **为什么关注**：一句话点出对行业 / 读者的意义（大白话）。
- **注解**：面向「IT 小白 / 非技术读者」的大白话说明，回答「这事到底是什么、跟我有什么关系」。可主动用生活化**比喻**、举一个贴近日常的小**例子**帮助理解；**禁止出现「通俗解释」四个字**。

### 2. ...

## 近期其他要闻

### 5. 标题（较早日期，形如 2026-07-31）

...
```

- 层级：分类用 `##`（今日要闻 / 近期其他要闻）；每条新闻用 `###`。
- 每条标题格式：`### 序号. 标题（日期）`，序号从 1 连续递增；当日日期用 `$DATE` 形式（YYYY-MM-DD），较早日期可用 `M月D日`。
- 每条**必须包含三项**，缺一不可：事件说明 + `- **为什么关注**` + `- **注解**`。
- 网页会把 AI 新闻标题渲染为蓝色，标题请直接、信息密度高，不要写成疑问句或口号。

### 1.3 文风

- **事件说明**：客观陈述事实，带关键数字（参数、价格、Star、融资额等），不堆砌形容词。
- **为什么关注 / 注解**：**大白话**，像给完全不懂技术的朋友解释。
  - 注解**不得**写成论文式长句；也**不得出现「通俗解释」四个字**（用「注解」即可）。
  - 为什么关注偏「对行业意味着什么」，注解偏「对我（普通读者）意味着什么」。
  - **注解必须代入「IT 小白」视角**：把专业概念翻译成生活化表达，可适度使用**比喻**、举贴近日常的**例子**。
    - 比喻：把抽象机制类比成日常事物（如「开源权重 ≈ 把祖传菜谱公开，谁都能照着做」；「多智能体 ≈ 一群各怀绝技的人分工搭积木」）。
    - 举例：说明「与我何干」（如「相当于你手机里多了个免费助理，写周报、查资料都能让它先干一遍」）。
    - 术语首次出现时，用括号补一句大白话（如「MoE（一种只调用部分『专家』来算、更省电的模型结构）」）。
    - 目标是让没技术背景的人读完也能大致明白发生了什么、为什么值得关心。

**注解写法对比（同一件事的两种写法，后者为标杆）：**

- ❌ 差（术语堆砌，小白读不懂）：MoE 架构通过稀疏激活降低了推理时的激活参数量，从而提升单位算力下的吞吐。
- ✅ 好（IT 小白友好）：这个模型用了「专家混合」的设计——相当于一家公司不养全能员工，而是把活儿拆给不同专才，谁擅长谁来、只调用需要的那一小撮人，所以又快又省电。

### 1.4 范例（标杆样式 —— 照此语气与结构，但内容必须按当日真实动态撰写，禁止照抄）

> 以下取自 2026-08-03 的真实产出，仅作风格锚点。

**今日要闻范例（序号 1）：**

```

阿里巴巴正式发布新一代基座大模型 Qwen3.8，旗舰版 Qwen3.8-Max 总参数量达 2.4 万亿……官方称 Qwen3.8-Max 权重预计下周开源……消息带动港股阿里巴巴早盘一度涨近 6%。
```

## 2. GitHub 趋势

### 2.1 数据源

- 优先用 `data/collected/gh_$DATE.json` 的 `daily` / `weekly` 真实数据（项目名、Star 数、描述）。
- 若为空，用 WebFetch 抓取 `https://github.com/trending?since=daily` 与 `weekly` 补全。

### 2.2 结构（严格照此）

```
## 一、今日榜（$DATE）

| 排名 | 项目 | 今日新增 Star | 注解 |
|:---:|------|:---:|---|
| 1 | [owner/repo](url)<br><span class="repo-desc">极简中文简介</span> | +数字 | 大白话注解（可多写） |
...（前 10 条）

> 📊 今日榜看点：一句话到一段的点评。

## 二、本周榜（本周日期范围，如 2026-07-27 ~ 2026-08-03）

| 排名 | 项目 | 总 Star | 本周新增 | 注解 |
|:---:|------|:---:|:---:|---|
| 1 | [owner/repo](url)<br><span class="repo-desc">极简中文简介</span> | 数字 | +数字 | 大白话注解 |
...（前 10 条）

> 🔍 趋势点评：一段，提炼本周主线。
```

- 标题中**不得出现 `since=` 字样**；本周榜标题写「本周日期范围」（周一 ~ 当天）。
- **今日榜**表格列：排名、项目、今日新增 Star、注解，前 10 条；后跟一句「今日榜看点」。
- **本周榜**表格列：排名、项目、总 Star、本周新增、注解，前 10 条；后跟「趋势点评」。
- **项目列格式（两块都一样）**：每个 `[owner/repo](url)` 链接之后，紧跟
  `<br><span class="repo-desc">极简中文简介</span>`，追加一行**极简短简介**（一句话讲清这个项目是干嘛的，与最右「注解」列**不重复**）。
- **注解**：大白话、可多写；数字与项目名来自真实抓取，**不编造**；无描述标「暂无描述」。GitHub 项目天然偏技术，注解应代入「IT 小白」视角：用一句话讲清「这个项目能拿来干嘛、为什么火」，必要时用生活化**比喻**或小**例子**降低理解门槛（例如把「多智能体协同」比作「一群各怀绝技的人分工搭积木」，把「星标暴涨」比作「这家店突然被所有人收藏」）。
- 「今日榜看点 / 趋势点评」为 blockquote（`>` 开头），放在各自榜单表格**之后**，用大白话点评，不堆数据。

## 3. 每日资讯速览（统一总结）

### 3.1 定位

**对当日整个网页内容做一次性统一总结**，而不是按栏目分块总结。要把「今日 AI 新闻」与「GitHub 日榜 / 周榜趋势」的全部内容拼装后，整体交给 AI 提炼成一段连贯摘要 + 一组关键要点。

### 3.2 生成方式（流水线中由 AI 完成）

1. 取当日 `data/raw/$DATE_ai.md`（含今日要闻 + 近期其他要闻）与 `data/raw/$DATE_github.md`（今日榜 + 本周榜）的**全文**，拼装为一份完整页面内容。
2. 将拼装后的完整内容一次性传入 AI，使用以下提示词：

   > 你是一名在语言理解和摘要生成方面训练有素的高级 AI。请阅读整个网页的内容并将其概括为一个简洁的摘要段落。目标是保留最重要的要点，提供一段连贯且易读的总结，使读者无需通读全文即可理解讨论的主要内容。请避免不必要的细节或偏离主题的旁枝末节。只输出结果，不要输出其他任何内容。

3. 在 AI 输出基础上，整理为两段式 Markdown（见 3.3）。两段都须由 AI 基于同一份完整内容生成，不得分块调用。

### 3.3 Markdown 结构（严格照此，仅两个 `##` 分区）

```
## 摘要

（一段连贯的概括性段落：点明当日 AI 行业整体趋势，并涵盖 GitHub 榜单反映的开发者关注方向。覆盖新闻与 GitHub 两端，不要分点。）

## 关键要点

- 一句话要点：覆盖一条重要新闻事件（保留关键数字 / 日期）。
- 一句话要点：覆盖另一条新闻事件。
- 一句话要点：覆盖 GitHub 日榜 / 周榜的某种趋势特征。
- （每条一句话，覆盖重要新闻事件与 GitHub 趋势特征，通常 6–10 条）
```

### 3.4 约束

- 所有信息必须来自当日 `data/raw/$DATE_ai.md` 与 `data/raw/$DATE_github.md`，禁止新增事实、数字或项目。
- 「摘要」为一段连贯文字，不列点；「关键要点」为条目式列表，每条一句话。
- 关键要点应覆盖：重要新闻事件（含今日要闻与近期要闻中的重点）+ GitHub 日榜 / 周榜的趋势特征。
- 若某日页面内容为空或 AI 总结未成功生成，`scripts/build_summary.py` 会渲染同款样式的兜底卡片，链接不会 404。

## 4. 发布前自检清单（必须全过，否则先修正再调用 filter.py）

- [ ] 今日要闻均为当天日期；其余严格时间倒序、无更晚日期插在前面。
- [ ] 每条 AI 新闻含「事件说明 + 为什么关注 + 注解」三项；注解不含「通俗解释」四字，且为 IT 小白友好的大白话（可含比喻 / 日常例子）。
- [ ] GitHub 今日榜 / 本周榜各 10 条；项目列含 `repo-desc` span；标题无 `since=`。
- [ ] 所有数字 / 项目名可追溯到抓取或搜索结果，无编造。
- [ ] 速览由两个 `##` 分区组成：`## 摘要`（一段连贯段落）与 `## 关键要点`（条目式列表，每条一句话）。
- [ ] 「摘要」点明当日 AI 行业整体趋势并涵盖 GitHub 榜单反映的开发者关注方向；「关键要点」覆盖重要新闻事件与 GitHub 趋势特征。
- [ ] 速览内所有数字 / 项目名 / 日期均能在完整版中找到出处。
- [ ] 任一项不通过 → 先修正 Markdown，再写入 `data/raw/$DATE_ai.md` / `data/raw/$DATE_github.md` / `data/raw/$DATE_summary.md` 并跑对应 `filter.py --section`。
